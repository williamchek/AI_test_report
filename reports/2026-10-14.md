## 🆕 Open-source project tests

### Anatomy — An "isometric illustration" skill for AI coding agents ⭐⭐⭐⭐⭐

- **What it is**: Turns technical concepts into an interactive virtual machine (SVG/WebGL isometric illustrations) for explaining ideas and documenting them. A brand-new project this week (created 10/8, ~8,700 stars, MIT).
- **How I tested it**:
  - `git clone --depth 1`. The README claims "only Node built-ins, zero dependencies" — verified: never ran `npm install` once.
  - Ran the example `node examples/dial-indicator/build.mjs`: produced a 136KB HTML file in 0.17s (6 SVGs, 354 paths, structure intact).
  - Ran `node examples/raptor-engine/build.mjs --audit`: after building a 1.6MB page, the geometry audit ran ~16 minutes, checking 80 pipes, 267 entities, 1.7M overlap pairs and 4,292 depth-sorting rules, finally printing **`audit passed`** — the flagship claim ("proves no pipe penetrates any part") actually runs, and passes.
- **Verdict & score**: ⭐5/5. Docs match implementation exactly; even the heaviest self-verification mechanism was run by hand and passed. Only nit: a full audit is CPU-hungry (but it's optional).
- **Who it's for**: Developers using Claude Code / Codex / OpenCode for technical writing, docs, blogs, or landing pages who need high-quality explanatory illustrations.
- **Link**: https://github.com/wheresryan22/anatomy

### Talorys — A personal AI assistant running in "your own Cloudflare account" ⭐⭐⭐⭐

- **What it is**: A personal AI assistant with chat, memory, todos, notes, and reminder scheduling; single-user, no telemetry, affordable on the free tier. Created 10/10, ~970 stars, MIT.
- **How I tested it**:
  - `git clone` + `npm install` (monorepo, ~2 minutes; Node 24 meets its Node ≥22 requirement).
  - `npm test`: shared, agent, and web workspaces all green. The first `create-talorys` run failed because a template file must be generated by `npm run build` — a "build before test" sequencing issue, not a bug; after building, all 4 test files / 52 tests passed.
  - `npm run dev` with all three services up failed when pages' workerd fought over a port; starting only the agent (`wrangler dev --local --port 8787`, mock-AI mode) worked.
  - Wired up the full chain by hand: `GET /api/health` returned `{"ok":true,...}` → login succeeded → `POST /api/chat` SSE stream normal (title → text deltas → done; the mock AI replied and created a conversation) → `POST /api/tasks` created a todo, `GET /api/tasks` read it back consistently (SQLite local persistence CRUD working).
- **Verdict & score**: ⭐4/5. The local dev loop (mock AI) fully verified. One star off because "real AI replies" still need Cloudflare Workers AI quota, and production deployment requires binding your own Cloudflare account — locally I could only verify the mock layer.
- **Who it's for**: Developers who want a personal AI assistant whose "data lives entirely in their own account" with no third-party SaaS in the loop; also a solid real-world reference architecture for Cloudflare Agents SDK + Durable Objects.
- **Link**: https://github.com/rociiu/talorys

## ✍️ Tech article deep-dives

### Anthropic's in-house version control Scion: when AI agents become the main force writing code, git is the first thing to break

- **Source**: Anthropic's official engineering blog, 2026-10-13 (titled "Creating in-house source control"). The original post couldn't be fetched directly this time; further reading via The Register: https://www.theregister.com/devops/2026/10/13/anthropic-reinvents-source-control-as-claude-floods-the-world-with-code/5302943
- **Core argument**:
  1. **The bottleneck moved**: Anthropic's monorepo went from ~2,500 merges/day in May to over 30,000 in September; main-branch history is nearly 100GB, CI does ~25M checkouts a day. Writing code is no longer the bottleneck — "developer infrastructure built for human scale (version control, builds, CI)" is.
  2. **Design assumptions flipped**: git was designed for "offline, distributed" humans, but the new world's primary customers are agents that are "by definition always online." The very features that make git great offline now drag down scale.
  3. **What Scion does**: moves work to the server; the working copy becomes optional. Changesets (entries in a write-ahead log) are the unit of work; ref changes are just a compare-and-swap on a single Spanner row; everything content-addressed, 99%+ cache hit rates at every layer; many CI jobs never check out at all — they just hit the API.
  4. **Claimed results** (all Anthropic's own numbers): 200× smaller CPU/memory footprint vs. their git-mirror architecture; checkouts two orders of magnitude faster (minutes → seconds); 25% CI CPU saved. A seven-person team shipped Scion, the Antique code-review tool, code search, and access control, and migrated everything in five months.
  5. **Not open source**: Anthropic says Scion is too bespoke to become a product, but expects more companies to hit the same wall within 6–12 months.
- **Why it matters**: First-hand evidence that in a world where agents write the code, what breaks first isn't model capability — it's the "harness" around the models: version control, CI, code review. For anyone building agent tooling, DevOps, or platform engineering, this reads like a design spec for "agent-scale infrastructure": API-first, server-side compute, local working copies as an option.
- **My take**: Two cold showers first. One: every key number is self-reported and unverified; the post also doesn't say how many of those 30,000 daily merges are real output versus agent-inflated merge volume. Two: this solution is unreplicable for 99% of teams (tied to Spanner, a giant monorepo, and not open source) — the pragmatic move for most is the opposite: squeeze sparse checkout, merge queues, and CI caching dry before ever building your own VCS. The most interesting question it doesn't address: with 30,000 merges a day, how does code review keep up? When review becomes "reviewing intent" rather than reading diffs line by line, does review become ritual? Read it as required reading on infrastructure design — but not as the answer to software quality in the agent era.

## 🛠️ Agent skill tests

### `tdd` (Matt Pocock) — A field manual for making the red→green loop "produce tests worth keeping" ⭐4.5/5

- **What it is**: Not a TDD primer but a field manual: test only the public interface (the seam), write the failing test first, slice vertically, no refactoring inside the loop. Near the top of the skills.sh leaderboard; free, zero install cost.
- **How I tested it**:
  - Read `SKILL.md`, `mocking.md`, and `tests.md` in full.
  - Followed the discipline to implement a shopping-cart checkout function `cartTotal` with Node 24's built-in `node:test`, in three slices: Slice 1 (totalling) — wrote the test first → 🔴 RED → minimal implementation → 🟢 GREEN; Slice 2 (SAVE10 = 10% off) — same RED→GREEN; Slice 3 (unknown promo code = no discount) — **the test passed immediately with no RED** — violating "Red before green"; on reflection the behavior was already covered by Slice 2, so this test was never a valid tracer bullet.
  - Honest note: during a GREEN phase I casually refactored an if/else into a lookup table — exactly violating the "refactoring is not part of the loop" rule. Both violations were called out precisely by the skill's rules.
  - Final `node --test`: all 3 tests green.
- **Verdict & score**: ⭐4.5/5. This skill is "self-correcting": the rules are concrete and actionable. Half a star off because it's mostly common sense for engineers already fluent in TDD.
- **Who it's for**: Developers who want their AI agents to write tests that "survive refactoring and aren't coupled to implementation details"; people standardizing team testing practices and killing useless tests and over-mocking. Not a beginner's intro to "what is TDD".
- **Link**: https://skills.sh/mattpocock/skills/tdd

## 🔌 MCP tests

### BetterWebSearch MCP v0.10.0 — A keyless, zero-config web-search MCP server ⭐4/5

- **What it is**: A web-search MCP server for AI agents, DuckDuckGo by default, no API key required, plus deep-research and article-extraction tools.
- **How I tested it**:
  - `npx -y better-web-search-mcp --help` — direct install **failed**: the `better-sqlite3` dependency couldn't fetch a prebuilt binary, fell back to node-gyp, then hit EPERM because the sandbox disallows `fchown`; npx failed the whole install and cleaned its cache.
  - Workaround: manually downloaded Node v24 headers (extracted with `--no-same-owner`), then `npm install --nodedir=...` to skip the tarball step — 203 packages installed successfully.
  - `--help` worked, listing 6 tools: `web_search`, `web_research` (`deep_search` is an alias), `web_extract`, `web_find` (site-scoped), `web_news`. Plus SQLite caching and optional Brave/Tavily keys.
  - Hand-wrote a Node script speaking stdio JSON-RPC: `initialize` ✓, `tools/list` ✓ (6 tools), `tools/call web_search{"query":"Model Context Protocol server","num_results":3}` ✓ — `isError: false`, returning real search results (title, url, snippet, relevance scores).
- **Verdict & score**: ⭐4/5. Keyless DuckDuckGo search genuinely works; all 6 tools verified. One star off because the native-module dependency makes one-shot `npx` installs fail outright in restricted environments — not the package's bug, but a real pitfall for newcomers.
- **Who it's for**: Developers who don't want to sign up for paid search keys (Brave/Tavily) and want to add web search to Claude Desktop / Cursor / Copilot quickly; people building daily research workflows.
- **Link**: npm `better-web-search-mcp`; intro post https://dev.to/phantompixeldev/i-built-a-better-web-search-mcp-for-ai-agents-no-api-key-required-51k2
