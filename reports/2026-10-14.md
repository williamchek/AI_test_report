## 🆕 開源新專案實測

### Anatomy — 給 AI coding agent 用的「等角插圖」skill ⭐⭐⭐⭐⭐

- **簡介**：把技術概念做成一台可互動的虛擬機器（SVG/WebGL 等角插圖），用來解釋原理、做文件插圖。本週新專案（10/8 建立，約 8,700 stars，MIT）。
- **實測過程**：
  - `git clone --depth 1`，README 宣稱「只用 Node 內建模組、零依賴」——屬實，全程沒跑過 `npm install`。
  - 跑範例 `node examples/dial-indicator/build.mjs`：0.17 秒產出 136KB 的 HTML（6 個 SVG、354 個 path，結構完整）。
  - 跑 `node examples/raptor-engine/build.mjs --audit`：build 產出 1.6MB 頁面後，幾何稽核跑了約 16 分鐘，檢查 80 條管線、267 個實體、170 萬組重疊關係與 4,292 條深度排序規則，最終印出 **`audit passed`**——官方主打的「證明沒有管線穿透任何零件」是真的會跑、且通過。
- **結論與評分**：⭐5/5。文件與實作完全一致，連最重的自我驗證機制都親手跑過且通過。唯一小缺點是完整稽核很吃 CPU 時間（但那是可選的）。
- **適合誰**：用 Claude Code / Codex / OpenCode 做技術寫作、文件、部落格或 landing page，需要高品質解說插圖的開發者。
- **連結**：https://github.com/wheresryan22/anatomy

### Talorys — 跑在「你自己 Cloudflare 帳號裡」的個人 AI 助理 ⭐⭐⭐⭐

- **簡介**：聊天、記憶、待辦、筆記、提醒排程的個人 AI 助理；單人使用、無遙測，免費額度可負擔。10/10 建立，約 970 stars，MIT。
- **實測過程**：
  - `git clone` + `npm install`（monorepo，約 2 分鐘裝完；Node 24 符合其 Node ≥22 需求）。
  - `npm test`：shared、agent、web 三個 workspace 全過。`create-talorys` 首次失敗是因為某模板檔要由 `npm run build` 產生——屬「先 build 再測」的流程問題而非 bug；build 後重跑，4 個測試檔、52 個測試全過。
  - `npm run dev` 三個服務同起時 pages 的 workerd 搶 port 失敗；改只起 agent（`wrangler dev --local --port 8787`，mock AI 模式）後成功。
  - 親手打通全鏈路：`GET /api/health` 回 `{"ok":true,...}` → 登入成功 → `POST /api/chat` SSE 串流正常（title → text deltas → done，mock AI 有回覆並建了 conversation）→ `POST /api/tasks` 建待辦、`GET /api/tasks` 讀回一致（SQLite 本地持久化 CRUD 正常）。
- **結論與評分**：⭐4/5。本地開發鏈路（mock AI）可完整驗證。扣一星是因為「真正的 AI 回覆」仍需 Cloudflare Workers AI 額度、正式部署要綁自己的 Cloudflare 帳號，本機只能驗到 mock 層。
- **適合誰**：想擁有「資料完全在自己帳號裡」、不經第三方 SaaS 的個人 AI 助理的開發者；也適合作為 Cloudflare Agents SDK + Durable Object 的實戰參考架構。
- **連結**：https://github.com/rociiu/talorys

## ✍️ 技術文章解析

### Anthropic 自研版本控制系統 Scion：當 AI agent 成為寫程式的主力，git 是第一個斷掉的環節

- **出處**：Anthropic 官方工程部落格，2026-10-13（標題 "Creating in-house source control"）。官方原文直連本次未能驗證，延伸閱讀附 The Register 報導：https://www.theregister.com/devops/2026/10/13/anthropic-reinvents-source-control-as-claude-floods-the-world-with-code/5302943
- **核心觀點**：
  1. **瓶頸轉移了**：Anthropic monorepo 每日合併從 5 月的約 2,500 次飆到 9 月的超過 30,000 次；主分支歷史近 100GB，CI 每天約 2,500 萬次 checkout。寫程式碼不再是瓶頸，「為人類規模打造的開發基礎設施（版本控制、建置、CI）」才是。
  2. **設計假設翻轉**：git 為「離線、分散式」的人類設計，但新世界的主要客戶是「定義上永遠在線」的 agents。讓 git 擅長離線工作的特性，反而在拖累擴展。
  3. **Scion 的做法**：把工作搬到 server，working copy 變成可選品。以 changeset（write-ahead log 的一筆）為工作單位，ref 變更只是 Spanner 單行的 compare-and-swap；全 content-addressed、各層快取命中率 99%+；很多 CI job 根本不用 checkout，直接打 API。
  4. **成果數字**（皆為官方自稱）：相較原本的 git 鏡像架構，CPU/記憶體 footprint 小 200 倍；checkout 快兩個數量級（分鐘→秒）；CI 省下 25% CPU。七人團隊五個月完成 Scion、code review 工具 Antique、code search 與存取控制並全量遷移。
  5. **不開源**：Anthropic 明言 Scion 太客製化、不會成為產品，但預期 6–12 個月內更多公司會撞上同類問題。
- **為什麼重要**：這是第一手證據，說明 agent 寫程式的世界裡，先斷掉的不會是模型能力，而是模型周圍的「harness」——版本控制、CI、code review。對做 agent 工具、DevOps、平台工程的人，這篇等於一份「agent 規模基礎設施」設計規格書：API-first、server-side 運算、把本地工作副本當可選品。
- **評點**：先潑兩盆冷水。第一，所有關鍵數字都是官方自稱，未經獨立驗證；文章也沒說那 30,000 次合併裡多少真是有效產出、多少是 agent 製造的合併量通膨。第二，這套解法對 99% 團隊不可複製（綁定 Spanner、巨型 monorepo，且不開源）——多數團隊的務實做法是反過來：先把 sparse checkout、merge queue、CI 快取榨乾，而不是自建版本控制。最值得玩味的是它沒談的問題：一天三萬次合併，code review 怎麼跟上？當審查變成「審意圖」而非逐行讀碼，review 會不會淪為儀式？把它當基礎設施設計的必讀，但別當成 agent 時代軟體品質的答案。

## 🛠️ Agent Skill 實測

### `tdd`（Matt Pocock）— 讓 red→green 迴圈「產出值得留下的測試」的實戰守則 ⭐4.5/5

- **簡介**：不是 TDD 入門教材，而是一份實戰守則：測試只測 public interface（seam）、先寫失敗測試、垂直切片、迴圈中不重構。skills.sh 排行榜前列，免費、零安裝成本。
- **實測過程**：
  - 完整讀完 `SKILL.md`、`mocking.md`、`tests.md`。
  - 照著守則，用 Node 24 內建 `node:test` 實作購物車結帳函式 `cartTotal`，切三個 slice：Slice 1（加總）先寫測試 → 🔴 RED → 最小實作 → 🟢 GREEN；Slice 2（SAVE10 打九折）同樣 RED→GREEN；Slice 3（未知 promo code 不打折）**測試直接通過、沒出現 RED**——違反「Red before green」，檢討後發現該行為已被 Slice 2 覆蓋，這個測試根本不是有效的 tracer bullet。
  - 誠實記錄：GREEN 階段順手把 if/else 重構成對照表，正好違反「重構不屬於迴圈」那條——兩次違規都被 skill 的規則準確點名。
  - 最終 `node --test` 3 個測試全通過。
- **結論與評分**：⭐4.5/5。這個 skill 是「會自我糾錯的」：規則具體、可操作。扣 0.5 是因為對熟 TDD 的資深工程師多為常識。
- **適合誰**：想讓 AI agent 寫出「經得起重構、不綁實作細節」測試的開發者；想統一團隊測試標準、杜絕無效測試與過度 mock 的人。不適合只想快速知道「TDD 是什麼」的新手入門。
- **連結**：https://skills.sh/mattpocock/skills/tdd

## 🔌 MCP 實測

### BetterWebSearch MCP v0.10.0 — 免金鑰、零設定的網頁搜尋 MCP server ⭐4/5

- **簡介**：給 AI agent 用的聯網搜尋 MCP server，預設走 DuckDuckGo、免 API key，另附深度研究與文章擷取工具。
- **實測過程**：
  - `npx -y better-web-search-mcp --help` 直接安裝**失敗**：依賴 `better-sqlite3` 的 native 編譯拿不到預編譯二進位，退回 node-gyp 又因沙盒不允許 `fchown` 而 EPERM，npx 整包失敗並清理快取。
  - 繞過：手動下載 Node v24 headers（`--no-same-owner` 解壓），用 `npm install --nodedir=...` 繞過 tarball 環節，成功裝完 203 個套件。
  - `--help` 正常，列出 6 個 tools：`web_search`、`web_research`（`deep_search` 為別名）、`web_extract`、`web_find`（限定站點）、`web_news`。另有 SQLite 快取與可選的 Brave/Tavily key。
  - 自寫 Node 腳本走 stdio JSON-RPC 實際呼叫：`initialize` ✓、`tools/list` ✓（6 tools）、`tools/call web_search{"query":"Model Context Protocol server","num_results":3}` ✓——`isError: false`，回傳真實搜尋結果（含 title、url、snippet、relevance 分數）。
- **結論與評分**：⭐4/5。免金鑰、DuckDuckGo 搜尋真的可用，6 個工具全過驗證。扣一分是因為依賴 native 模組，`npx` 一鍵安裝在受限環境會直接失敗——非套件本身的 bug，但對新手是坑。
- **適合誰**：不想申請 Brave/Tavily 等付費搜尋 key、想給 Claude Desktop / Cursor / Copilot 快速加上聯網搜尋能力的開發者；做每日研究型工作流程的人。
- **連結**：npm `better-web-search-mcp`；介紹文 https://dev.to/phantompixeldev/i-built-a-better-web-search-mcp-for-ai-agents-no-api-key-required-51k2
